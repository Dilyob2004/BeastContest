# BeastContest 0.4

Локальная платформа контестов: .NET 10, C#, Blazor Server, Identity, PostgreSQL.

## Запуск на Windows

1. Установите Docker Desktop с Linux containers / WSL 2. Для первого запуска нужен интернет.
2. Дважды нажмите **Start-BeastContest.bat** в корне проекта.
3. Скрипт запускает Docker Desktop при необходимости, собирает сайт и среду проверки, поднимает PostgreSQL, сервер и Judge Worker, дожидается готовности и открывает http://localhost:5080/account/login.

На сайте доступна только форма входа. Регистрации и веб-настройки администратора нет. Без авторизации страницы контестов, задач и результатов закрыты.

## Запуск на macOS

Нужен Docker Desktop для Mac (на Apple Silicon — версия «Mac with Apple chip»). В Settings → Resources выделите Docker не меньше 4–6 ГБ памяти.

Файлы `.command` в корне проекта запускаются двойным щелчком (откроется Терминал), их можно вызвать и из Терминала:

| Windows | macOS | Что делает |
|---|---|---|
| Start-BeastContest.bat | Start-BeastContest.command | Создаёт `.env` с паролем базы, запускает Docker Desktop, собирает и поднимает контейнеры, открывает страницу входа |
| Stop-BeastContest.bat | Stop-BeastContest.command | Останавливает контейнеры, данные сохраняются |
| Create-Admin.bat | Create-Admin.command | Создаёт `admin` со случайным паролем и показывает его один раз |
| Create-User.bat | Create-User.command | Создаёт участника, логин и пароль сохраняются в `credentials/` |
| Reset-Admin-Password.bat | Reset-Admin-Password.command | Задаёт `admin` новый случайный пароль |

Логика скриптов — в `scripts/mac/*.sh`. Участника можно создать сразу с именем: `./Create-User.command student01 "Иван Петров"`. Если macOS не даёт открыть файл двойным щелчком, выполните в папке проекта `chmod +x *.command scripts/mac/*.sh` или запустите `bash scripts/mac/start.sh`.

## Создание аккаунтов

Для участника запустите **Create-User.bat** при работающем сервере. Введите логин (Enter — student01). Случайный пароль из 6 символов и логин сохраняются в отдельный TXT в папке **credentials**. Файл создаётся только для успешно созданного аккаунта; дубликаты логинов не перезаписываются. Папка исключена из Git и Docker-образа. Передавайте файл только соответствующему участнику. Для проверки интерфейса на этом компьютере откройте приватное окно браузера и войдите с данными из TXT. Адрес localhost работает только на компьютере сервера; LAN пока не настроена.


Для автоматического создания администратора после запуска сервера дважды нажмите **Create-Admin.bat**. Он создаст логин `admin` со случайным паролем и покажет пароль в окне после успешного создания. Скопируйте пароль перед закрытием окна. При повторном запуске существующий аккаунт и его пароль не меняются.

После запуска сервера откройте PowerShell в папке проекта. Создайте своего администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Create-BeastUser.ps1 -Login admin -Role Admin -DisplayName Organizer
```

Создайте участника:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Create-BeastUser.ps1 -Login student01 -Role Participant -DisplayName Student
```

Команда попросит пароль: ввод скрыт, пароль не передаётся аргументом команды. Участнику требуется ровно 6 символов, администратору — 10–128; минимум три разных символа. Логин: 3–40 латинских букв, цифр, точек, дефисов или подчёркиваний. Дубликат логина отклоняется, существующий аккаунт не перезаписывается. Готовых общих паролей нет.

Можно вызвать непосредственно команду приложения:

```powershell
docker compose exec web dotnet BeastContest.Web.dll --create-user admin --role Admin --name Organizer
```

В разделе «Участники и доступ» администратор может создать участника, заблокировать его, сбросить пароль и удалить аккаунт. При создании генерируется пароль из 6 символов: его можно показать и скачать с логином в TXT. После закрытия карточки пароль повторно не показывается. Создание администраторов остаётся доступным через команду на сервере. Пароли хешируются Identity.

## Остановка и повторный запуск

Дважды нажмите **Stop-BeastContest.bat**. Пользователи, задачи и контесты сохраняются в томе PostgreSQL. Для повторного запуска используйте Start-BeastContest.bat. Не удаляйте Docker volumes и не используйте `docker compose down -v`, если хотите сохранить данные.

При ошибке запуска окно останется открытым с сообщением. Логи: `docker compose logs web`. Порт 5080 должен быть свободен. Нативный сайт и Docker-сайт одновременно на одном порту запускать нельзя.

## Режим разработки

Нужны .NET SDK 10 и Docker Desktop:

```powershell
.\scripts\Start-BeastContest.ps1
```

PostgreSQL запускается в Docker, сайт — через dotnet. Откройте http://localhost:5080 вручную; остановка сайта — Ctrl+C. Для создания аккаунта нативной командой задайте `ConnectionStrings__Database` и запустите приложение с `--create-user LOGIN --role Admin` вместо веб-сервера. Проще создавать аккаунты через Docker-команду выше: оба режима используют одну базу.

## Что работает

- Русский и английский интерфейсы, светлая и тёмная темы.
- Обязательный вход, роли Admin / Participant, блокировка и сброс пароля.
- После входа администратор открывает отдельную панель /admin. Участнику доступны задачи, результаты и личный чат с организаторами; административные страницы закрыты и по прямой ссылке.
- Чат хранится в PostgreSQL, новые сообщения появляются сразу, показываются последние 100 сообщений. Сообщение — до 2000 символов. Администратор выбирает участника, участник видит только свой диалог.
- Добавление задач в библиотеку: названия и условия RU/EN, ввод/вывод, пример, темы, сложность, лимиты и PDF до 5 МБ на язык.
- Новые задачи доступны администраторам; участники видят их после старта включающего их контеста.
- Создание контестов из библиотеки, выбор ICPC / баллов, запуск и завершение.
- В «Результатах» сначала выбирается конкретный завершённый контест. Реальные отправки формируют таблицу ICPC или баллов; демонстрационные таблицы помечены.
- При равных баллах выше тот, кто раньше набрал итоговый результат. Время от старта и попытки показаны по каждой задаче и участнику, включены в CSV и замороженные снимки. В ICPC порядок определяется решёнными задачами и штрафом.
- Проверка решений на C++, C#, Java, Python, Go, Haskell и JavaScript. Можно загрузить файл или ввести код; примеры для каждого языка — в `docs/examples`.
- Чекеры: по токенам, построчно, числа с погрешностью ε и свой чекер на C++ с testlib.h.
- Веса тестов (0–1000) и группы, засчитываемые целиком, в контестах по баллам. Балл и результат каждого теста видны в очереди проверки.
- Импорт тестов из JSON или ZIP (`.in/.out`, `.ans`, Polygon `01/01.a`, папки `input/output`).
- Редактирование задачи: условие, PDF, примеры, лимиты и чекер. Запланированные контесты получают изменения сразу.
- Вердикты, статусы задач, очередь, таблица идущего контеста и чат обновляются без перезагрузки через PostgreSQL LISTEN/NOTIFY.
- Административная страница `/admin/judge`: очередь, активные проверки, ошибки, состояние Worker и фильтры отправок.
- Перепроверка одной отправки с прежними тестами или всего контеста с сохранёнными/обновлёнными тестами. Причина и прежние результаты сохраняются в журнале.
- Ручная заморозка таблицы участников и публикация текущих результатов. Администратор видит текущие результаты даже при заморозке; снимок сохраняется после завершения контеста.
- Скачивание CSV с заголовками RU/EN, результатами ICPC/баллы и соблюдением заморозки для участников.
- PostgreSQL и миграции EF Core, импорт старых JSON-черновиков с сохранением исходника.

**Следующие этапы:** управление допуском участников, LAN, резервные копии и нагрузочная приёмка на 100 участников. Правила проверки и ограничения языков описаны в [docs/JUDGE.md](docs/JUDGE.md).

Пока сайт доступен только на компьютере организатора: публикация портов привязана к localhost. Настройка подключения других компьютеров по LAN и HTTPS — следующий этап.

## Данные

- `beastcontest_postgres-data`: PostgreSQL, пользователи, задачи, PDF и контесты.
- `beastcontest_beast-data`: ключи cookies Docker-сайта.
- `.env`: автоматически созданный пароль базы; не передавать другим и не добавлять в Git.
- `src/BeastContest.Web/App_Data`: ключи при нативном запуске.

При смене режима запуска потребуется повторный вход, поскольку ключи cookies различаются. Для резервного копирования нужны дамп PostgreSQL и ключи приложения; автоматическое резервирование ещё не реализовано.

## Проверки

```powershell
dotnet build BeastContest.slnx
dotnet run --project tests/BeastContest.Checks --no-build
```

База из `.env` должна работать. Проверки используют отдельную случайную схему PostgreSQL и HTTP-сервер на 5081, затем удаляют тестовую схему. Пользовательская схема public не меняется. Подробности — docs/VERIFICATION.md.

## English quick start

Run **Start-BeastContest.bat** on Windows with Docker Desktop / Linux containers installed. It starts the database, server and Judge Worker and opens the login page. No public registration is available. Create accounts from the server terminal using `scripts/Create-BeastUser.ps1 -Login admin -Role Admin`; the password is entered invisibly. Use **Stop-BeastContest.bat** to stop without deleting data. All seven languages are supported; LAN deployment and load testing are still pending.

## Тесты при создании задачи

В разделе «Тесты задачи» нажмите «Добавить тест» для каждой пары входа и ожидаемого ответа. Поля можно заполнить вручную или загрузить отдельные `.txt` через «Вход из TXT» и «Ответ из TXT». Файлы: UTF-8 (с BOM или без), до 256 КБ каждый; до 100 тестов и 4 МБ на набор. Загрузка заменяет выбранное поле, сохраняя пробелы и переводы строк. Затем нажмите «Добавить в библиотеку»: задача и скрытые тесты сохраняются вместе. Позже их можно изменить через «Тесты задачи» на странице задачи. Импорт набора JSON также доступен.

Эти тесты предназначены для Judge и не показываются участникам. Публичные примеры размещайте в тексте условия или PDF. Ранее сохранённые публичные примеры остаются видны в своих задачах.

Аккаунт и выход находятся справа в шапке. Администратор видит «Сообщения участников», участник — «Чат с администратором».

## Если забыт пароль администратора

Сообщение `Cannot load library libgssapi_krb5.so.2` в старых Docker-образах означало отсутствие необязательной библиотеки Kerberos при попытке подключения Npgsql. Если затем напечатано `Password reset for admin`, пароль успешно изменён. Новые образы web/judge устанавливают `libgssapi-krb5-2`; обычный запуск через Start-BeastContest.bat пересобирает их.

При работающем сервере запустите **Reset-Admin-Password.bat**. Он заменит пароль аккаунта admin случайным и покажет его после успешного сброса. Старый пароль больше не подойдёт. Если аккаунта нет, используйте Create-Admin.bat. Скопируйте новый пароль перед закрытием окна; в файл он не сохраняется.

Все PowerShell-скрипты находятся в папке scripts. В корне находятся BAT-файлы запуска, остановки, создания администратора и сброса его пароля. Остальные файлы проекта и конфигурации остаются на своих местах.

## Удаление задачи

Администратор открывает задачу из библиотеки, нажимает «Удалить задачу», проверяет её название и подтверждает «Удалить окончательно». Условие, PDF и скрытые тесты удаляются вместе без восстановления. Демонстрационные задачи, задачи из любого контеста (включая черновики и завершённые) и задачи с отправками удалить нельзя: это сохраняет историю соревнований. Права и связи проверяются сервером; одновременное добавление задачи в контест защищено блокировкой строки PostgreSQL.




## Скрытые тесты задач

Администратор открывает задачу в библиотеке и нажимает «Тесты задачи». Можно добавить пары ввода/ожидаемого вывода вручную или импортировать JSON-массив объектов Input/Output. Пример: docs/examples/sum-tests.json. Импорт заменяет список в редакторе; в базу изменения попадут только после «Сохранить».

Лимиты: 100 тестов, 256 КБ UTF-8 на поле, 4 МБ на набор/файл. Пустые строки разрешены, пробелы и переводы строк сохраняются. Неизвестные/пропущенные поля и неправильный JSON отклоняются. При одновременном редактировании устаревшее сохранение отклоняется. Версия — счётчик изменений, история прежних наборов пока не хранится.

Тесты доступны только администратору и не публикуются в условиях или PDF. Изменения библиотеки не меняют тесты уже запущенного контеста: его снимок фиксируется при старте. Проверка администратора вне зачёта использует текущий сохранённый набор.


## Решения из файлов и автоматическая проверка

Добавлены загрузка исходников в редактор, очередь PostgreSQL и Judge C++/Python. Пошаговый пробный контест, правила оценивания и текущие ограничения — в [docs/JUDGE.md](docs/JUDGE.md).




Удаление участника требует подтверждения. Администраторов и свой аккаунт удалить нельзя. Отправки, результаты и записи чата сохраняются в базе; удалённый аккаунт теряет доступ, исчезает из списка и выбора адресата чата. Повторное создание того же логина создаёт нового участника и не переносит старые результаты. Старые пароли автоматически не меняются: формат из 6 символов действует при создании и сбросе пароля участника.

Задачи нумеруются цифрами 1, 2, 3… В контесте номер соответствует порядку его задач и совпадает с колонкой таблицы результатов/CSV. В библиотеке номер соответствует порядку доступных задач и сохраняется при поиске. Сложность и фильтр по ней видит только администратор.

## Участники и расписание

При создании контеста выберите аккаунты участников, задачи и время начала. Часовой пояс задаётся рядом со временем (по умолчанию UTC+05:00). Если время не указано, получится черновик с ручным запуском. Для расписания нужны сохранённые тесты у всех задач: снимок тестов фиксируется при планировании. Сайт автоматически откроет контест в заданное время без отдельной кнопки запуска.

В существующем контесте список можно изменить через «Участники контеста» → «Сохранить участников». Для черновика или ещё не начавшегося контеста доступна настройка расписания. Новая версия не записывает пользователей в старые контесты автоматически: организатор назначает их явно.

Участник без записи видит сообщение и кнопку выхода. Записанный участник до старта видит обратный отсчёт; задачи, PDF, отправки и чат закрыты на сервере. При начале страница открывается автоматически. При нескольких записях приоритет у идущего контеста (с более ранним стартом), затем ближайшего предстоящего, черновика и последнего завершённого. В результатах участника сразу выбран текущий контест; доступен также выбор своих завершённых контестов.

В списке задач показывается личный статус для текущего контеста: зелёный — есть принятое решение, красный — неудачная проверка/компиляция, нейтральный «Проверяется» — отправка в очереди или выполняется. Принятое решение остаётся зелёным после следующих неудачных попыток. Ошибка сервиса не считается неудачным решением. Без отправок подсветки нет. Статусы обновляются каждые три секунды.
