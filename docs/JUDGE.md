# Отправки и Judge 0.4

Запуск: `Start-BeastContest.bat`. Compose поднимает PostgreSQL, сайт и отдельный Worker. При первой сборке скачиваются среды семи языков; это требует интернета и нескольких гигабайт места. Нативный запуск одного сайта не запускает Worker.

## Пробный контест

1. Создайте задачу «Сумма двух чисел» в библиотеке.
2. Откройте её скрытые тесты, импортируйте `docs/examples/sum-tests.json` и сохраните.
3. Создайте контест с этой задачей и нужными языками, выберите аккаунты участников и запустите вручную либо задайте будущее время старта с часовым поясом. До старта участники видят экран ожидания. Для первого опыта установите 2000 мс и 256 МБ.
4. Войдите участником. Откройте задачу, выберите файл из `docs/examples`: `sum.cpp`, `Sum.cs`, `Main.java`, `sum.py`, `sum.go`, `Main.hs` или `sum.js`. Код появится в редакторе, язык определится автоматически.
5. Выберите контест и нажмите «Отправить решение». Вердикт появляется в истории сразу после проверки, без обновления страницы.
6. Завершите контест из панели администратора. В результатах выберите этот контест.

Администратор может выбрать проверку вне зачёта, не запуская контест. Она использует текущие сохранённые тесты. Контест использует снимок тестов и лимитов, сделанный при ручном запуске или сохранении расписания. Ранее запущенные контесты без снимка следует заменить новым пробным контестом.

## Форматы и правила

- Один UTF-8 файл до 64 КБ. Поддерживается BOM. Файл заменяет код редактора; затем его можно исправить. Загрузка сама по себе не отправляет решение.
- Расширения: `.cpp`, `.cc`, `.cxx`, `.py`, `.cs`, `.java`, `.go`, `.hs`, `.js`. Все семь языков подключены к выполнению.
- C++20; C# / .NET 10 (явные `using`, без автоматически добавляемых импортов); Java — класс `Main` без `package`; Go — `package main`; Haskell — `main`; JavaScript — Node.js. Один исходный файл, стандартная библиотека, без загрузки внешних пакетов.
- Минимальный лимит задачи: Java 128 МБ, C# и JavaScript 64 МБ, остальные 16 МБ. Это нижняя граница приёма отправки, а не гарантия достаточной памяти для любой программы. Память включает среду исполнения.
- Образ содержит GCC 13, Python 3.12, OpenJDK 21, Go 1.22, GHC 9.4 и Node.js 18 из Ubuntu 24.04, .NET 10 из SDK-образа. Точные версии пакетов зависят от сборки образа; закрепление образа по digest для каждого контеста ещё предстоит.
- Способ проверки ответа задаётся в задаче (раздел «Проверка ответа» в форме задачи), подробности — в разделе «Чекеры» ниже. По умолчанию — сравнение по токенам.
- Баллы: каждая задача стоит 100 баллов; результат — доля набранных весов тестов от 100 с учётом групп, округляется вниз (см. «Веса и группы тестов»). Берётся лучшая отправка задачи. При одинаковом итоге выше тот, кто раньше набрал его: для каждой задачи берётся время первой отправки с её лучшим положительным баллом, для участника — самое позднее из этих времён. Время считается от старта контеста в целых секундах. При совпадении баллов и времени участники делят место.
- ICPC: первая принятая отправка, минуты от начала контеста плюс 20 минут за каждую предыдущую WA/TLE/MLE/RE/OLE. CE и ошибки сервиса не штрафуются. Нерешённые задачи не добавляют штраф. Равные результаты делят место.
- Отправки администраторов в контест (проверка задач организатором) в таблицу результатов, CSV и замороженные снимки не попадают. Отправки удалённых аккаунтов участников остаются.
- Время `ЧЧ:ММ:СС` и число попыток показаны по участнику и каждой задаче. Это время отправки от старта, а не время выполнения программы. Попытки включают все отправки, даже CE, ожидающие проверки и отправленные после лучшего результата; их общее число не влияет на место. Без положительного результата время обозначается `—`. Старые замороженные снимки без этих полей показывают `—` до публикации текущей таблицы; скрытые результаты не раскрываются.
- Участник видит только собственные отправки. Скрытые входы, ответы и stderr выполняемой программы не выводятся. Диагностика компиляции доступна автору.

## Чекеры

В форме задачи (создание или «Редактировать задачу») выберите способ проверки:

- **По токенам** — слова и числа должны совпасть, пробелы и переводы строк между ними не важны. Поведение по умолчанию и для всех старых задач.
- **Построчно** — строки должны совпасть точно; пробелы в конце строк и пустые строки в конце вывода игнорируются.
- **Числа с погрешностью** — нечисловые токены совпадают точно, числа — если |x − y| ≤ ε · max(1, |y|), где y — ответ жюри. ε от 1e-12 до 1, по умолчанию 1e-6. NaN и бесконечность не принимаются.
- **Свой чекер (testlib)** — исходник C++20 до 64 КБ, `#include "testlib.h"` (testlib 0.9.45, MIT, лежит в `judge/testlib.h` и копируется в образ). Чекер компилируется в отдельной песочнице и кешируется Worker по хешу исходника. Для каждого теста он запускается как `checker input.txt output.txt answer.txt` в собственном контейнере без сети, отдельно от программы участника; лимит 15 секунд и 512 МБ. Код 0 — верно, 1 и 2 — неверный ответ, любой другой код или превышение лимитов — ошибка чекера: отправка получает «Ошибку сервиса», чтобы не выдать случайный вердикт. Ошибки компиляции чекера и его сообщения видны только в проверке администратора вне зачёта; участник видит общее сообщение.

Способ проверки входит в снимок задачи, как тесты и лимиты. Участник видит способ проверки и ε рядом с лимитами задачи.

## Веса и группы тестов

У каждого теста есть «Баллы» (0–1000, по умолчанию 1) и необязательная «Группа» (до 32 латинских букв, цифр, `-`, `_`). В контестах по баллам результат задачи = ⌊100 · набранные баллы / сумма баллов⌋. Тест без группы приносит свои баллы, если пройден. Группа приносит сумму баллов своих тестов, только если пройдены все её тесты. Примерам можно поставить 0 баллов. Сумма баллов набора должна быть больше нуля. В ICPC веса не влияют на результат.

Worker сохраняет итоговый балл и короткий результат каждого теста (AC, WA, TL, ML, RE, OL, CF); их видно в `/admin/judge`. Старые отправки при обновлении получили балл по прежнему правилу (равные веса), поэтому таблицы завершённых контестов не меняются.

## Импорт тестов

Кроме JSON (`[{"Input":"…","Output":"…","Points":1,"Group":""}]`, поля Points и Group необязательны), набор можно загрузить ZIP-архивом. Архив разбирается в памяти, на диск ничего не распаковывается. Поддерживаемые пары: `NAME.in` + `NAME.out` или `NAME.ans`; `NAME` + `NAME.a` (Polygon); `input/NAME` + `output/NAME` (также `in`/`out`, `inputs`/`outputs`, `answers`); `inputNAME.txt` + `outputNAME.txt`. Прочие файлы пропускаются. Тесты сортируются по имени с учётом чисел (2 раньше 10). Лимиты: архив до 16 МБ, до 1000 записей, 100 тестов, 256 КБ на файл и 4 МБ всего, UTF-8 без нулевых символов. Дубликаты и тесты без пары отклоняются. Импорт заменяет список в редакторе; запись в базу — кнопкой «Сохранить».

## Редактирование задач

Кнопка «Редактировать задачу» на странице задачи открывает условие, PDF, примеры, лимиты и способ проверки. Сохранение сразу обновляет снимки **запланированных и ещё не начавшихся** контестов с этой задачей; то же происходит при сохранении тестов. Начавшиеся и завершённые контесты сохраняют свой снимок: чтобы применить к ним изменения, запустите перепроверку контеста с обновлёнными тестами. Черновики контестов делают снимок при запуске.

## Обновления без перезагрузки

Сайт слушает канал PostgreSQL `beast_events` (LISTEN/NOTIFY). Worker и сайт отправляют событие при постановке в очередь, начале и окончании проверки, перепроверке, заморозке таблицы и новом сообщении чата. События содержат только идентификаторы; страницы перечитывают данные обычными проверенными сервисами, поэтому чужие данные через события не утекают. Пачки событий (например, перепроверка всего контеста) объединяются, и каждая страница обновляется один раз. История отправок, статусы задач, очередь проверки, таблица идущего контеста и чат обновляются сразу. Запасной опрос остаётся раз в 30 секунд (очередь — раз в 10 секунд ради состояния Worker). После потери соединения с базой сайт переподключается и обновляет открытые страницы.

## Исполнение

Один Worker проверяет одно решение за раз. На пользователя разрешены три ожидающие отправки. Очередь хранится в PostgreSQL; просроченное задание подхватывается повторно, максимум три попытки. Аренда обновляется каждые 10 секунд и истекает через 60 секунд.

Каждый тест запускается в новом контейнере без сети, секретов, томов проекта и Docker socket: непривилегированный UID, read-only filesystem, cap-drop ALL, no-new-privileges, один CPU, 64 процесса/потока и лимит памяти без дополнительного swap. Временная папка ограничена 64 МБ. Компиляция ограничена 60 секундами, 1024 МБ памяти, 512 МБ временных файлов и 128 процессами/потоками. Лимит открытых файлов: 1024 при компиляции, 256 при запуске; размер отдельного файла — до 256 МБ, но общий размер переносимых артефактов — до 16 МБ. Вывод ограничен 1 048 576 символами на поток. К лимиту времени теста добавлены 500 мс на подключение Docker; это начальная реализация wall-clock контроля, её точность требует дальнейших измерений.

Для .NET и Java бюджет управляемой кучи составляет половину памяти контейнера; для Node.js ограничивается old-space. Остальное требуется среде исполнения. MLE определяется по OOM-kill контейнера; исключение нехватки памяти внутри виртуальной машины может дать RE.

Worker имеет доступ к Docker socket и является доверенным сервисом. Сайт и программы участников этого доступа не получают. Контейнеры удаляются после теста; старые контейнеры с меткой Judge убираются автоматически. Доверенный процесс наблюдения от root завершает контейнер через 120 секунд даже при сбое Worker; компилятор и решение запускаются от UID 65534. Исходники передаются через stdin доверенному загрузчику во временную область /solution (16 МБ); программа участника не может менять её файлы. Таймаут самого решения дополнительно контролирует Worker.

Логи: `docker compose logs --tail 100 judge`. Если Worker выключен, новые отправки остаются в очереди до его запуска. `/health` проверяет сайт и базу, а не готовность Worker.

## Мониторинг

Администратору доступна страница `/admin/judge`: глобальные счётчики ожидающих и выполняемых заданий, просроченных аренд и ошибок сервиса за последние 24 часа. Список последних 50 отправок фильтруется по вердикту, языку и контесту. Фильтры не меняют глобальные счётчики. Участникам страница и сервис данных закрыты.

Worker обновляет heartbeat каждые 5 секунд; после 20 секунд без обновлений отображается offline. Heartbeat подтверждает работу процесса, а не успешную проверку всех компиляторов. Список отправок обновляется сразу при изменениях, состояние Worker — раз в 10 секунд. Показываются до 10 последних записей Worker. При перезапуске создаётся новый идентификатор, старая запись остаётся offline.

## Перепроверка

В `/admin/judge` кнопка «Повторить» возвращает одну отправку в очередь с её сохранёнными тестами. Это подходит для повторения после сбоя инфраструктуры. Для исправления тестов сначала сохраните их в библиотеке, затем выберите контест в фильтре и нажмите «Перепроверить выбранный контест». Выберите «Текущие тесты и лимиты библиотеки», укажите причину и подтвердите запуск. Весь контест проверяется независимо от фильтров языка/статуса и ограничения списка в 50 строк.

Обновление тестов применяется ко всем отправкам выбранного контеста, включая будущие. Частичное обновление тестов одной отправки не допускается. Можно перепроверять начавшиеся и завершённые реальные контесты; пустые тесты отклоняют операцию целиком. При выборе сохранённых тестов снимки не меняются.

Исходный код и время отправки сохраняются: штраф ICPC считается от первоначальной отправки. Старые вердикты сбрасываются, пока Worker не завершит повторную проверку; таблица результатов в это время может показывать промежуточные значения. Попытки Worker обнуляются, активная аренда отзывается. Запись результата старым Worker после этого не принимается. Повтор одного запроса не создаёт второй запуск.

Журнал показывает последние 20 запусков: кто, когда, почему и сколько отправок перепроверил. В таблице базы `Rejudges` также сохраняются прежние вердикты, диагностика и снимки тестов; доступ к ней нужен для подробного аудита. Автоматический откат и очистка журнала пока отсутствуют, поэтому резервная копия базы должна включать его.

## Заморозка таблицы

В «Результатах» по-прежнему выбирается завершённый контест. Над списком доступны ссылки на таблицы идущих контестов; администратор также может открыть таблицу из страницы контеста. Кнопка «Обновить» загружает текущую разрешённую пользователю версию.

Администратор нажимает «Заморозить таблицу участников»: в PostgreSQL сохраняется точный снимок таблицы на этот момент. Участники получают только этот снимок, а администратор продолжает видеть текущую таблицу с поясняющей надписью. Новые отправки, поздние вердикты и перепроверки не изменяют замороженную таблицу. Собственная история отправок участника остаётся доступной.

Завершение контеста не снимает заморозку. Для раскрытия итогов администратор нажимает «Опубликовать текущие результаты»; участники увидят их после обновления таблицы. Повторная команда заморозки не заменяет сохранённый снимок. Заморозка ручная, без расписания и автоматического раскрытия. Отправки продолжают приниматься по обычным правилам контеста.

## Экспорт CSV

Откройте реальный контест в «Результатах» и нажмите «Скачать CSV». Экспорт доступен также для идущего контеста; его данные могут измениться после следующих проверок. Демонстрационные и незапущенные контесты не экспортируются.

Файл содержит название контеста, систему оценивания, версию таблицы, время замороженного снимка UTC, место, имя, итог, время и число попыток участника. Для каждой задачи 1, 2 и далее выгружаются результат, время и попытки; для ICPC добавляется общий штраф. Заголовки соответствуют выбранному языку интерфейса RU/EN. При пустой таблице файл содержит только заголовки.

Участник скачивает ту же разрешённую ему версию, что видит на сайте: при заморозке — сохранённый снимок. Администратор получает текущие результаты. В имени файла указано `frozen` или `current`; доступ повторно проверяется при скачивании, заблокированные аккаунты и отозванные cookies не допускаются.

Формат: UTF-8 с BOM, разделитель `;`, строки CRLF, поля в двойных кавычках. Excel можно открыть через импорт CSV с кодировкой UTF-8 и разделителем `;`, если настройки системы выбирают другой разделитель. Потенциальные формулы (включая результаты ICPC с `+`/`-`) предваряются апострофом, чтобы сохраняться как текст. Файл содержит только таблицу, без исходников, тестов, паролей и диагностики.

Следующие этапы: LAN, резервное копирование, затем нагрузочное испытание на 100 участников. Текущий этап ещё не является приёмкой для соревнований с недоверенными участниками.
